# Submission notes

Track: Startup. Theme: Build for Your World.

**One line:** Startup due diligence that is allowed to say "don't build this": every number traced to a source, for founders, funds and studios.

**Problem:** Founders spend months building things they could have ruled out in an afternoon, and existing validators return confident numbers nobody can check. Funds and studios read far more applications than they can verify.

**Solution:** Interview, live web research, a verdict enforced by code, a system design, a clickable prototype and legal first steps. Funds screen batches against their own thesis.

**How Meta's models are used:** Muse Spark 1.3 for reasoning, structured output, web search grounding and PDF reading. Muse Image for prototype visuals. Muse Voice Transcribe for spoken answers.

**What is technically hard:** Keeping a model honest in code: a provenance layer checks each claim against the URLs the search returned, market maths and scores are computed outside the model, and generated prototypes run in a sandbox with a CSP and self-repair.

**Who pays (hypotheses, untested):** Founders per report; funds, accelerators and venture studios per seat or per screened application.
